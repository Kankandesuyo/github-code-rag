# GitHub Code RAG 产品成熟化设计

## 1. 产品目标

把当前已经可运行、可鉴权、可容器化的单管理员代码分析工具，升级为新手可以独立完成完整任务的产品。用户无需理解 FastAPI 或 RAG，即可导入 GitHub 仓库、看到分析状态、阅读项目概览、针对源码提问，并导出可复用的项目报告与 README。

本阶段服务个人部署和作品展示，同时保留未来演进为多用户 SaaS 的接口边界，但不提前开发注册、团队权限、配额和计费。

## 2. 成功标准

- 首页直接表达产品用途，并提供清晰的首次使用路径。
- 仓库导入过程有明确状态和可恢复的错误提示，重复导入不会产生重复项目。
- 项目工作台统一承载概览、代码问答、项目报告和 README，不要求用户记忆 repository_id。
- 回答必须附带真实来源文件；没有足够证据时明确说明，不能伪装成确定结论。
- 项目列表可以查看、重新打开和删除；删除同时清理元数据、分析快照与向量数据。
- API 保持向后兼容，现有鉴权、限流、安全过滤、Docker 和 CI 能力不退化。
- 自动测试覆盖核心用户旅程，完成本地 Uvicorn 实机验证。

## 3. 方案选择

采用“产品闭环优先、AI 增强随后”的渐进方案。相比只增加分析功能，它能解决 Demo 难以使用的问题；相比直接改造多用户 SaaS，它避免现在引入数据库迁移、租户权限和计费带来的高复杂度。

## 4. 信息架构

前端采用单页工作台，分为四个状态：

1. 欢迎与导入：说明用途、输入 GitHub URL、展示示例和环境能力。
2. 导入处理中：展示当前阶段，禁止重复提交，并保留可理解的失败原因。
3. 项目工作台：展示仓库概览、索引统计、来源信息和可执行操作。
4. 分析结果：代码问答、项目报告和 README 使用独立标签页呈现。

项目列表作为持久入口。用户刷新页面后仍可恢复最近项目，不再依赖手工保存 repository_id。

## 5. 后端边界

### Repository Catalog

新增仓库目录服务，负责读取项目 manifest、返回产品需要的摘要、记录创建和更新时间，并提供一致的删除操作。路由层只处理 HTTP 校验和鉴权，不直接拼装磁盘数据。

目录响应预留 `owner_id` 字段。单管理员阶段固定为空，未来 SaaS 化时可在服务层注入当前用户并实施归属过滤，而不修改前端主要数据结构。

### Analysis API

保留现有同步接口以维持兼容。加载响应补充结构化统计和下一步操作信息。报告与 README 继续复用 manifest 缓存，避免重复扫描。

### Deletion API

新增受保护的项目删除接口。repository_id 必须通过既有格式校验；删除范围严格限制在 `repos/` 对应目录和 Chroma 对应集合。文件清理和向量清理由服务层集中执行，任一步失败都返回明确错误并写服务器日志。

## 6. 数据流

```text
GitHub URL
  -> URL 与权限校验
  -> 远程文件发现与安全过滤
  -> 安全分析快照 + Chroma 索引
  -> 项目 manifest / catalog 摘要
  -> 工作台
       -> 基于来源的代码问答
       -> 静态分析项目报告
       -> README 草稿
       -> 项目删除
```

manifest 是当前单机版本的项目元数据来源。所有目录查询容忍单个损坏 manifest：跳过损坏项目并记录警告，不能让整个项目列表不可用。

## 7. 错误处理与可观测性

- API 返回稳定、可展示的错误信息，不把密钥、绝对路径或内部异常堆栈暴露给浏览器。
- 前端区分配置缺失、GitHub 限流、仓库无可分析文件、认证过期和服务器故障。
- 每个请求保留现有安全响应头；日志使用模块 logger 记录 repository_id、阶段和异常类型，不记录仓库源码、Token 或用户密码。
- `/health` 保持轻量；新增的目录损坏不能影响健康检查。

## 8. 安全设计

- 所有业务接口继续经过单管理员 Session 或 API Key 鉴权。
- 新增删除接口要求 CSRF 校验；API Key 客户端保持兼容。
- 删除路径使用受控 repository_id 映射和根目录包含检查，禁止接收任意路径。
- 前端不保存管理员密码、Session Token、API Key 或 CSRF Token 到 localStorage。
- 远程文件继续经过路径、敏感文件、软链接、文件大小、数量和总字节限制。
- `owner_id` 只是兼容字段，不宣称已实现租户隔离；未来启用多用户前必须迁移到事务数据库并对所有查询实施所有权校验。

## 9. 测试与验收

- 服务测试：目录读取、损坏 manifest、删除成功、删除不存在项目和根目录边界。
- API 测试：项目详情、删除鉴权与 CSRF、向后兼容。
- 前端静态契约测试：工作台关键区域、错误映射、删除确认和认证处理。
- 回归测试：完整 pytest、compileall、pip check、git diff check。
- 实机测试：启动 Uvicorn，验证首页、健康检查、鉴权状态、项目列表、OpenAPI，并确认进程可干净退出。

## 10. 非目标

本阶段不实现多人注册、OAuth、团队协作、计费、云任务队列和水平扩容。上述能力需要独立的 SaaS 设计周期，不能通过一个未生效的 `owner_id` 字段冒充完成。
